Y-Axis Slot System — 3 Approaches

How should the chart decide which axes are visible when more series compete for a side than the max allows?

A

Declaration Order (First-come, first-served)

Keep left / right. First N series declared on that side get visible slots; overflow goes to hidden. No new API fields.

B

Explicit Priority Field

Add axisPriority: int to YAxisConfig. Higher priority wins a visible slot. Ties broken by declaration order.

  • Full user control
  • Stable across reordering

Cons

  • Extra field to set on every axis
  • Burden on caller to manage priorities
C

Slot System with Selection Swap ⭐ Recommended

Remove leftOuter/rightOuter. Each side has maxAxesPerSide (default 3). Declaration order fills slots. Selecting a "voted-out" series swaps its axis in, bumping the lowest-priority visible one to hidden.

  • Swap state adds complexity
