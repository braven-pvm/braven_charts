Design — Section 1: API Changes

What changes at the call site. Does this look right?

1. YAxisPosition enum Breaking (deprecation)

enum YAxisPosition { left, right, hidden, @Deprecated('Use YAxisPosition.left instead') leftOuter, // silently maps to left at runtime @Deprecated('Use YAxisPosition.right instead') rightOuter, // silently maps to right at runtime }

Existing code still compiles. The deprecated values resolve to left/right in YAxisConfig's constructor via _normalizePosition().

2. New AxisSwapMode enum New

enum AxisSwapMode { /// Swapped axis persists after deselection (default) sticky, /// Swapped axis reverts to original slot order on deselection revert, }

3. BravenChartPlus widget parameters New

BravenChartPlus( // --- existing --- series: [...], xAxisConfig: ..., // --- new --- maxAxesPerSide: 3, // max visible axes per left/right side axisSwapMode: AxisSwapMode.sticky, // sticky | revert onSeriesSelected: (String seriesId) { ... }, // legend or data-point tap onSeriesDeselected: (String seriesId) { ... }, // tap again or tap elsewhere onAxisSwapped: ({ // fires when slot changes required String promotedAxisId, required String demotedAxisId, }) { ... }, )

4. Programmatic API via BravenChartController New

final controller = BravenChartController(); // select a series by ID — triggers axis swap if needed controller.selectSeries('heat_strain'); // deselect — triggers revert if axisSwapMode == revert controller.deselectSeries('heat_strain'); controller.clearSelection(); // read current slot state controller.visibleAxisIds; // List<String> — currently in slots controller.overflowAxisIds; // List<String> — voted out, available for swap controller.selectedSeriesId; // String? — currently selected

Controller is optional — charts without one still respond to legend/data-point taps internally.

Does this API surface look right? Any names or fields to change?
